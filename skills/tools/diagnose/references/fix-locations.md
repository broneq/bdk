# Where a fix belongs

Name one location per problem. When two fit, take the one closest to the cause: a skill that gives a wrong instruction is the cause, not the role that followed it.

| Location                     | The problem is here when                                                                                                                                                                | Typical evidence                                                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Stage skill                  | A `/bdk:` stage skill told the main thread to do the wrong thing, in the wrong order, or did not say when to stop.                                                                      | The main thread repeats a step the skill asks for; a refusal follows a step the skill names.                                 |
| Role contract                | A role (`implementer`, `verifier`, `lead`, ...) acted against or without its contract: it read too much, ran the whole suite, retried the same command, or reported in the wrong shape. | A subagent's slice shows the behaviour; D1, D2, D4, D5 or D7 cites it.                                                       |
| Dispatch package or template | The package of a ticket lacked what the role needed (files, commands, acceptance), or gave it something wrong.                                                                          | The agent searches for something the package should have named; `bdk log show` of the ticket's report says what was missing. |
| Kernel                       | A `bdk` command refused a correct call, gave a wrong `instead`, was slow (D8), or a guard blocked a legal action.                                                                       | A refusal whose `instead` the agent followed and was refused again; a guard block on an allowed command.                     |
| Plan                         | A task was too large, too vague, or depended on another task it did not name, so it was redispatched, narrowed or escalated.                                                            | D6 with the reason from the ledger; one task far above the median (D8).                                                      |
| Project                      | The project's tests, settings, code or tools caused the problem: a flaky or slow test, a missing `tools.test` scope, a broken build.                                                    | The same test fails without a code change; `tools.*` settings name a whole-suite command only.                               |

Kernel, stage skill, role contract and dispatch template problems are BDK problems: they go to `## For a BDK issue`. Plan and project problems are the project's: record them with `bdk log add learning` when a Change is active.
