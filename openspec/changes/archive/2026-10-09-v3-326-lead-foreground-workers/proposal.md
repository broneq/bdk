## Why

Tracks #326.

A `bdk:lead` started its review workers without the `run_in_background` field, and the host (Claude Code 2.1.295) started all three as background agents. The lead then wrote its own wait loop on the workers' task output files and lost 9.3 of a 14-minute `debug-fix` run (fixture `plugins/bdk/evals/fixtures/diagnose-run/`, lead transcript lines 35 to 49; `bdk diagnostics report` lists it as `slow-call`). The skill texts say "foreground" but never name the parameter; with the current host, a model that leaves the field out gets a background agent. Speed is goal 1 of v3 (CLAUDE.md, "Goal of this line").

## What Changes

- Every `Agent` call a skill of the `bdk` plugin writes names its run mode as the parameter: `run_in_background: false` for an agent the skill waits for (every worker of a lead, every block an orchestrator or a main-thread block starts), `run_in_background: true` only for a lead an orchestrator starts in the background on purpose (`execution.lead: background`), and `run_in_background: false` for that lead when `execution.lead` is `foreground`.
- The lead skills `review-round`, `pr-review-round` and `execute-waves` and the agent `bdk:lead` name `run_in_background: false` on every worker call. `pr-review-round` writes its worker calls as `subagent_type: "bdk:<agent>"` like the other skills, so the tests that read Agent calls see them.
- `bdk:lead` never polls a worker's task output file and never sleeps waiting for a worker.
- A workspace test fails and names the skill and the agent when a paragraph of a `SKILL.md` that starts `subagent_type: "bdk:<agent>"` names neither `run_in_background: false` nor `run_in_background: true`, next to the `models.<agent>` test.
- The eval case `auto-review-first-round` grades that no worker `Agent` call of the lead lacks `run_in_background: false`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `bdk-plugin`: new requirement "Every Agent call names its run mode", with the test and the acceptance signal of #326.
- `bdk-auto-review`: "Eval cases of the review stage" adds the foreground grader of `auto-review-first-round`.

## Impact

- `plugins/bdk/skills/*/SKILL.md` (every skill that starts a `bdk:` agent), `plugins/bdk/agents/lead.md`, `plugins/bdk/tests/agent-models.test.ts` (or a sibling test), `plugins/bdk/evals/auto-review-first-round/graders/`, `plugins/bdk/evals/README.md`.
- User docs: `docs/concepts/agents.md` (how a lead starts its workers), and `docs/reference/` regenerated by `pnpm docs:reference` (the agent and skill texts it reads).
- The "To resolve in the spec" item of #326 (whether orchestrators that start a lead in the background keep that explicit with `run_in_background: true`) is resolved in design.md, D1: yes.
- Out of scope: how the host decides background versus foreground when the field is missing (a Claude Code behaviour, not BDK's); the `slow-call` detector itself (#322).
