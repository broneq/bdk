## Why

Tracks #322.

A user, and the BDK maintainers, cannot analyse after the fact how a BDK run went: which stages and agents ran, how long each took, what it cost, and where time and tokens were wasted. The draft line had diagnostics (`draft/v3-1`, #110), built on an always-on kernel journal and an opt-in hook on every tool call; both are gone with the kernel, and the per-tool-call hook is the kind of cost v3 must not pay by default (goal 1, speed; `docs/v3-draft1/run-b1/2026-10-07-bdk-v3-findings.md`). Its known defect, #157, marked a whole session missing when one transcript was missing.

What v3 has instead is enough: Claude Code writes a transcript per session and per subagent under `~/.claude/projects/<project>/`, and every stage writes its run files under `.bdk/runs/<change>/` (architecture design, "Run state, run artifacts and resume": "turns and time come from transcripts").

## What Changes

- New skill `/bdk:diagnose-run [<change> | <session-id>]`: runs read-only on a new agent `bdk:analyst`, reads the run files of a Change and the host transcripts of its sessions, and writes `.bdk/runs/<change>/diagnostics.md`: the stage timeline, every agent with its wall time, turns, tokens and cost share, retries and blockers, and the waste found, each claim with a citation (`<file>:<line>` of a transcript or a run file) and a suggestion of where the fix belongs.
- New agent `bdk:analyst` (default model `sonnet`, tools `Read`, `Grep`, `Glob`, `Bash`, `Write`, `Skill`), and with it the `models.analyst` role (spec `bdk-cli/config`, "Every agent is a models role").
- New command group `bdk diagnostics` with one verb, `bdk diagnostics report`: parses the transcripts of a session or of every session that names a Change into numbers (per stage, per agent, per model) and the findings of deterministic detectors with citations. Added because the eval of the plain skill showed a model does not count transcripts reliably: it gave no tokens or cost per stage or agent and missed repeated commands (design D2, "Measurement").
- A missing or unreadable transcript is reported for that agent only; the other agents of the session are still counted (#157).
- No hook, no journal, no always-on recording (design D4).
- User docs: a Guide page for diagnostics, the Concepts pages that list skills and agents, and the regenerated Reference.

## Capabilities

### New Capabilities

- `bdk-diagnose-run`: the `/bdk:diagnose-run` skill and the `bdk:analyst` agent: inputs, how sessions are found, the report file and its sections, citations, read-only behaviour.
- `bdk-cli/diagnostics`: the `bdk diagnostics report` command: transcript location, session selection, the counts, the cost share, the detectors and their citations, partial transcripts.

### Modified Capabilities

- `bdk-cli/config`: `analyst` joins the roles of `models` ("Every agent is a models role").

## Impact

- `plugins/bdk/skills/diagnose-run/`, `plugins/bdk/agents/analyst.md`, `plugins/bdk/src/diagnostics/` (new slice, its row in `src/slices.ts`), `src/main.ts`, `src/config/domain/settings.ts` (role list), eval cases `plugins/bdk/evals/diagnose-run-*` with a recorded fixture run.
- `/bdk:cli` (`skills/cli/SKILL.md`) names the new command, as `scripts/cli-skill.test.ts` requires.
- User docs: new `docs/guide/diagnostics.md` (in the Guide sidebar, linked from `docs/guide/index.md` and `docs/guide/footprint.md`), `docs/concepts/agents.md`, `docs/concepts/cli-config-hooks.md`, `docs/concepts/run-state.md`, and `docs/reference/` regenerated by `pnpm docs:reference`.
- Out of scope: settings for detector thresholds and a command that prints the transcript events around a citation (no measurement asked for them; the analyst reads the cited lines with `Read`), and any always-on recording.
