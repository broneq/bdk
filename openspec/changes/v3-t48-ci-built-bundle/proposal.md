# Proposal

## Why

Scope: #114. Tracks #114.

`dist/bdk.mjs` (about 960 KB), 83 JSON Schemas under `schema/` and six agent adapters under `agents/` are generated by `pnpm build`, committed, and guarded by `git diff --exit-code dist/ schema/` and `export agents --check` in CI. Every PR that touches `kernel/src/` must commit rebuilt output, and `schema/settings.json` changes with every new settings key, so two parallel PRs always conflict on files nobody can merge by hand: the only resolution is to rebuild. Only three of these have a consumer outside the tests: the bundle and the adapters (read by the host when the plugin runs) and `schema/settings.json` (fetched by IDEs through the modeline URL). The other 82 schema files are read by contract tests only, and the guard that keeps a committed generated file equal to its source is itself the chore that causes the conflicts.

The bundle and the adapters must exist in the ref users install from, because the plugin installs from git and runs no build step (kernel-architecture, Bundle). That requires them on the distribution ref, not on `main` or on feature branches.

## What Changes

- Every generated file is built, not committed: `dist/bdk.mjs`, `schema/settings.json`, `schema/pipeline.json`, `schema/state/`, `schema/cli/output/`, `schema/cli/common/{version,refusal}.json` and the six adapters `agents/{lead,reader,reviewer,runner,scout,worker}.md` are ignored by git. Hand-written files stay tracked: `schema/cli/commands.json`, `commands.schema.json`, `cli/common/list-page.json`, and the v2 agents until T42 removes them.
- `pnpm build` becomes the one generator: bundle, schemas, then `export agents --host claude`. `prepare` runs it after `husky`, so a fresh worktree has everything for `claude --plugin-dir`; `test:e2e` and `test:contract` run it first so a test never reads a stale generated file.
- CI drops `git diff --exit-code dist/ schema/` and the `export agents --check` step; both would compare a build with itself. A contract test replaces them: every file the generators write is ignored and untracked.
- A release job builds the tagged commit and force-pushes its tree plus `dist/`, `schema/` and `agents/` to a `release` branch, and tags that commit `dist-v<version>`. It runs only when release-please created a release; `workflow_dispatch` with a `tag` reruns it.
- The `bdk` entry of `.claude-plugin/marketplace.json` changes from `"source": "./"` to a `github` source with `"ref": "release"`.
- The settings modeline URL changes from `.../v<version>/schema/settings.json` to `.../dist-v<version>/schema/settings.json`, because release-please's tag `v<version>` is on `main`, which no longer holds the schema.
- Documentation that states "committed bundle" is updated: `CLAUDE.md`, `CONTRIBUTING.md`, `README.md`, the guide under `docs/guide/`, ADR-0002 (an amendment note, never a rewrite) and `docs/V3-IMPLEMENTATION-PLAN.md` T10.
- **BREAKING** for contributors only: a checkout of `main` or `staging/v3` has no bundle until `pnpm install`, and cannot be installed as a plugin from git. Users are not affected: they install from `release`.

Out of scope: moving generated files into `dist/` (rejected: the host's `agents` manifest field takes files, not directories, and replaces the default scan, so adapters must stay in `agents/`; `schema/cli/commands.json` refers to `output/...` by relative path); `kernel/src/` changes beyond the modeline URL; replacing the generated `rules export --claude` projection (T-other, still committed); T42's removal of the v2 agents.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `kernel-architecture`: `Bundle`, `CI pipeline` and `Tests per slice` (built, not committed; no diff guard); new `Generated outputs` and `Distribution ref`.
- `kernel-settings`: `Settings JSON Schema` (no committed copy; modeline on the `dist-v<version>` tag).
- `kernel-state`: `State JSON Schema` (not tracked).
- `kernel-pipeline`: `Pipeline file` (the generated `schema/pipeline.json` is not tracked).
- `kernel-cli/config`: `bdk config schema` (equal to the build's schema; example URL).
- `kernel-cli/export`: `bdk export agents` (the build writes the adapters; CI does not run `--check`).

## Impact

- CI: `.github/workflows/tests.yml` (two steps removed), `.github/workflows/release-please.yml` (publish job, `workflow_dispatch`). `.github/release-please-config.json` untouched.
- Plugin packaging: `.claude-plugin/marketplace.json`; verified against https://code.claude.com/docs/en/plugins/marketplace-reference (Plugin sources: `github` takes `repo`, `ref`, `sha`; `ref` is a branch or tag) and https://code.claude.com/docs/en/plugins-reference (Fields: `agents` takes `.md` files and replaces the default scan). `plugin.json` `version` is bumped by release-please on each release, which is what makes installed copies update from a moving branch.
- Build and tests: `kernel/build.mjs`, `kernel/scripts/export-schemas.ts` (comment), `package.json` (`prepare`, `test:e2e`, `test:contract`), `.gitignore`, `.gitattributes`, one new contract test, `kernel/src/config/schema/schema.ts` (modeline tag) with its tests.
- Docs: `CLAUDE.md`, `CONTRIBUTING.md`, `README.md`, `docs/guide/`, `docs/adr/0002-kernel-runtime-node-typescript.md`, `docs/V3-IMPLEMENTATION-PLAN.md`.
- Related: T42 (turns `agents/` fully generated, the six adapter lines become `/agents/`), T50 (3.0 release uses this pipeline).

## Open questions

1. **Distribution ref: `release` branch or the release tag.** Recommendation: a `release` branch (one stable marketplace entry, no per-release edit of `marketplace.json`). A user who needs an old release pins it by `sha` in their own entry.
2. **Contributor testing of an unreleased ref.** Recommendation: `claude --plugin-dir <worktree>` after `pnpm install`, as today; no install from a feature branch.
3. **`$id` of the state schemas** names `.../bdk/v3/schema/state/`. Recommendation: leave it, it is an identifier no consumer fetches; verify that in the implementation task before closing.
