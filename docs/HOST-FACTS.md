# Host facts (Claude Code)

Live answers to the host questions that the v3 kernel's gates and guards depend on (design, "What We Did NOT Decide", "Live checks"; plan task T01). Every row is backed by a recorded payload in `tests/fixtures/host-payloads/<version>/`, with machine-specific values replaced by placeholders (`<HOME>`, `<PROJECT>`, `<PLUGIN_ROOT>`, `<CLAUDE_TMP>`, `<SESSION-n>` and so on). Rows that contradict the design name the design line and the task that has to absorb the difference. The design text itself is not edited.

- **Host version:** Claude Code 2.1.281, probed 2026-09-24. Rows marked 2.1.282 were probed 2026-09-25.
- **Probe:** plugin `bdk-probe` in `tests/host-probe/`, loaded with `--plugin-dir`. It is never shipped.
- **Method:**
  - _headless_: `claude -p` driven by `run-headless.sh`, with `--permission-mode default`.
  - _checklist_: an interactive session started by `probe-session.sh`. The user's default permission mode is `auto`, and each payload's `permission_mode` shows the mode it ran in.
  - _docs_: the published reference, cited by URL.

## `bdk stage enter` fallback

Not needed. `UserPromptExpansion` fires for plugin skills typed by the user (`upe-fires`), so T10 does not add `bdk stage enter` and the "`!` blocks call only `ctx` and `next`" boundary stays as designed. T24 has to take in two related differences from the design:

- the namespaced `command_name` (`upe-name`);
- the fact that a nested `claude -p "/bdk:plan"` also counts as user-typed (`upe-headless`).

## Rerunning the probe

Run this after a Claude Code upgrade, or when a result above is in doubt. Always work from a scratch directory, never from this repo (both scripts refuse to run inside it).

```sh
REPO=~/projects/bdk
VERSION="$(claude --version | cut -d' ' -f1)"
mkdir -p /tmp/bdk-probe && cd /tmp/bdk-probe && git init -q

# 1. Headless checks (about 5 minutes; PROBE_MODEL defaults to haiku).
sh $REPO/tests/host-probe/run-headless.sh
sh $REPO/tests/host-probe/node-sqlite.sh

# 2. Interactive checks: follow tests/host-probe/CHECKLIST.md (six short sessions).

# 3. Collect into tests/fixtures/host-payloads/$VERSION/ and check for leaks.
node $REPO/tests/host-probe/collect.mjs "$VERSION" \
  $(for c in tools-list pre-bash pre-write pre-edit pre-multiedit pre-notebookedit agent-fg agent-bg \
      skill-tool-plan allowed allowed-control node-sqlite upe-typed bash-mode locked \
      session-end-clear session-end-term session-end-kill9; do printf '%s=%s--* ' $c $c; done)
(cd $REPO && uv run pytest tests/unit/host_probe/)

# 4. Compare with the previous version and update the table above.
diff -r $REPO/tests/fixtures/host-payloads/2.1.281 $REPO/tests/fixtures/host-payloads/$VERSION
```

`collect.mjs` exits 1 when a check has no recording; `session-end-kill9` is expected to be missing, and the other checks are still written.

Every file differs in step 4 even when nothing changed, because placeholder numbering, timestamps and the model's replies vary between runs. Read the diff for changes in the fields the table depends on: `hook_event_name`, `tool_name`, the `tool_input` keys, `command_name`, `command_source`, `reason`, and whether `agent_id` is present. A payload that appears or disappears (the `recordings` count in `_probe`) is also a result. A rerun on 2.1.281 differed only in the optional Bash `description` key. The `bash-mode` and `locked` checks also need a transcript excerpt saved as `<check>--Transcript.json` before collecting, because hook payloads do not show what ran or what the model saw. `CHECKLIST.md` shows how.
