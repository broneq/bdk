# JavaScript — Language Rules (2026)

Principles for modern JavaScript (ES2024+/ES2025, Node 22+/24+) codebases. Applied during planning, implementation, and review when `javascript` is in `.bdk/settings.json` `languages`. These cover plain JavaScript; type-system concerns live in the TypeScript rules.

- **ESM with named exports is the baseline.** Default new code to `"type": "module"` and `import`/`export`; CommonJS adds interop friction and blocks modern tooling. Prefer named exports over a default — they survive refactors and tree-shake cleanly.
- **Break circular dependencies — they hide initialization-order bugs.** Cyclic imports make module side effects fire in an unpredictable order and produce partially-initialized values. Restructure to a one-directional graph or pass the dependency as a parameter instead of importing it at module scope.
- **`const` by default; `let` only when reassignment is real.** `const` signals intent and prevents accidental rebinding; `var` hoists unpredictably and has no place in new code. Remember `const` freezes the binding, not the value — an object behind a `const` is still mutable.
- **Don't mutate shared state — use the immutable operations.** Prefer `toSorted`, `toReversed`, `with`, and `toSpliced` over their mutating counterparts, object/array spread for shallow copies, and `structuredClone` for deep ones. In-place mutation of shared data is a classic source of action-at-a-distance bugs, especially across async boundaries.
- **`async`/`await` over raw `.then` chains.** Awaited code reads top-to-bottom, produces usable stack traces, and makes `try/catch` the single error path. Reserve raw promise combinators for genuine concurrency, not sequential flow.
- **Parallelize independent async work; await sequentially only when ordered.** `await`-in-a-loop over independent tasks serializes them needlessly — collect the promises and use `Promise.all` (fail-fast) or `Promise.allSettled` (when every outcome matters). Await in sequence only when one step truly depends on the previous.
- **No floating promises — every async path has an error handler.** An unhandled rejection can crash the process; a forgotten `await` silently drops failures. Always `await` or `.catch()`, lint for floating promises, and keep `process.on('unhandledRejection')` only as a last-resort net.
- **Make long-running async work cancellable with `AbortController`.** Thread an `AbortSignal` through fetches, streams, and your own async functions so stale work can be torn down; `AbortSignal.timeout()` and `AbortSignal.any()` cover deadlines and composite cancellation. Uncancellable async wastes resources on results no one will read.
- **`===` always; `==` never.** Loose equality coerces in ways that surprise (`0 == ""`, `null == undefined`) and hides type confusion. Use strict equality and convert types explicitly when you mean to.
- **`??` for nullish fallbacks, `?.` for nullish access.** `||` treats `0`, `""`, and `false` as "missing" and silently replaces valid values — use `??` when only `null`/`undefined` should trigger the default. Use `?.` to traverse possibly-absent structure, but don't let it mask a logic error that should throw.
- **Chain errors with `Error.cause`; model failures as typed errors.** Wrap a low-level failure in a higher-level one with `{ cause }` so the original stack and context survive. Define named error classes carrying structured fields (`statusCode`, `field`, `retryable`) rather than encoding state in message strings — and never swallow an error to silence it.
- **Reach for the modern stdlib instead of hand-rolling.** `Object.groupBy`/`Map.groupBy` replace reduce-based grouping, `Array.prototype.at` handles negative indexing, logical-assignment operators (`??=`, `&&=`, `||=`) tidy defaults, and iterator helpers (`.map`/`.filter`/`.take` on iterators) process large or infinite sequences lazily without materializing intermediates. Native paths are clearer and faster than utility-library equivalents.
- **Top-level `await` belongs in leaf modules, not shared libraries.** It blocks every downstream importer until it resolves, so a delay in a shared utility cascades through the dependency graph. Confine it to entry points and config loading; wrap library async in an explicit init function.
- **Pure functions in the core; side effects at the edges.** Keep computation free of I/O, logging, and DOM/global mutation so it stays testable and composable; push side effects to module boundaries and inject them. Don't run side-effectful code at import time — initialization that takes work belongs in a function, not the module top level.
- **Mind the classic foot-guns.** Floating-point equality (`0.1 + 0.2 !== 0.3`), `NaN !== NaN` (use `Number.isNaN`), mutating a collection mid-iteration, and `this` rebinding in detached methods or callbacks all produce silent wrong answers. Use arrow functions or explicit binding to keep `this` stable.

## Security

These are stack-specific failure modes on top of the language-agnostic security rules (trust boundaries, injection, secrets). They apply to both browser and Node.js JavaScript.

- **Never turn untrusted input into code.** `eval`, the `Function` constructor, `setTimeout`/`setInterval` with a string argument, and dynamic `import()` of a user-controlled path all execute attacker input. Use schema-validated config, lookup tables, or an allowlist of module paths instead.
- **`textContent` for untrusted text; sanitize before any HTML sink.** Assigning user data to `innerHTML`, `insertAdjacentHTML`, or `document.write` is a DOM-XSS vector. Render text with `textContent`; when you genuinely need markup, sanitize through DOMPurify or the native Sanitizer API, and enforce Trusted Types as defense-in-depth.
- **Treat untrusted keys as prototype-pollution vectors.** Deep-merging or assigning from attacker-controlled JSON lets `__proto__`/`constructor`/`prototype` keys mutate `Object.prototype` and poison every object. Use `Object.create(null)` or `Map` for untrusted data, reject those keys, and avoid known-vulnerable deep-merge utilities.
- **`execFile`/`spawn` with an argument array — never `exec` with user input.** `child_process.exec` runs through a shell, so any interpolated user data becomes shell metacharacters. Pass arguments as array elements to `execFile` or `spawn` so there is no shell to inject into.
- **Validate user-controlled URLs against SSRF.** Before fetching a user-supplied URL, allowlist the scheme (`http`/`https`), block internal ranges and cloud metadata endpoints, resolve and re-check the host, and disable automatic redirect following. An unchecked outbound request is a pivot into your internal network.
- **Confine user file paths to a base directory.** Resolve the path with `path.resolve` and assert it still starts with the intended root to stop `../` traversal; account for Windows device names and absolute-path overrides. Prefer an allowlist of known filenames over sanitizing arbitrary input.
- **Bound regex against ReDoS.** Catastrophic backtracking from a pathological input freezes the single-threaded event loop and takes the whole service with it. Avoid nested quantifiers, cap input length, never run a user-supplied pattern, and test regexes with adversarial inputs.
- **Cryptographic randomness for anything security-bearing.** `Math.random` is predictable — use `crypto.getRandomValues` for tokens, keys, and session IDs, and `crypto.randomUUID` for identifiers. Predictable tokens are guessable tokens.
- **Constant-time comparison for secrets.** Comparing tokens, HMACs, or auth cookies with `===` leaks length and content through timing. Use `crypto.timingSafeEqual` (or an equivalent) so comparison time doesn't depend on how much matched.
- **Validate `postMessage` origin; isolate `target="_blank"`.** Always check `event.origin` against an expected value before acting on a `postMessage` — the sender is untrusted. Add `rel="noopener"` to cross-origin `target="_blank"` links so the opened page can't reach back through `window.opener`.
